# Improvement plans

These plans translate recorded gate evidence into bounded work. They do not authorize changing a target repository or promote a generated candidate.

## engram-project-ontology

- Artifact: `project-ontology`
- Disposition: **revise**
- Preserve:
  - project-local vocabulary before Organon mapping
  - exact public source citations and nonclaims
  - every conflict, uncertainty, and anti-collapse distinction already established
- Required changes:

### Organon ontology

- Revision: Downgrade `authorized-human`, pane Entity, canonical Interface, input Action, watch World, GitHub Claim, and local Order to candidate or unmapped status unless each missing dependency is supplied. For the human Agent, name the Entity identity criterion, ordered States, Persistence witness, Interpretation, and selected Action. For the pane, explicitly identify ordered pane States and the validation sequence that witnesses Persistence of the identity tuple. Treat the anchor initially as a Representation governed by routing Rules and Constraints; promote it to Interface only after naming the Entity, indexed Boundary, and represented permitted Transformations. Rebuild the World mapping with named participating Entities, selected Environment, Constraints, included Sense/Action causal paths, and a common Invariant across guide and snapshot access. Treat a broker request as a request Record or Representation until a named asserting Agent is carried; keep the authorization regime an Order candidate until a plurality of qualifying Agents and recurring coordination Relations are established. Rename the causal path to 'remote message to guarded tmux input' unless a downstream State/Change is observed and joined; any causal-efficacy claim must add matched Causal Contribution witnesses. Leave 'source of truth' as project idiom, or map a specific raw-capture Map to Reference only after declaring its Denotation, Scope, decision procedure, Constraints, omissions, and distortions. Make these qualifications explicit in the machine manifest rather than relying on global candidate prose.
- Critical violations:
  - `authorized-human → organon:Agent` is marked exact, but the cited user/chat admission checks establish only configured message eligibility. They do not establish the human as an Entity with a named Invariant and Persistence witness or join that Entity's Interpretation to an Action.
  - Several positive refinements omit constitutive dependencies that the project itself acknowledges as unresolved. The pane lacks a complete Entity Persistence witness; the canonical anchor is called an Interface without identifying whose Entity Boundary it composes; and `watch-accessible-domain → World` lacks a complete participant/Sense/access-path account and an explicit common Invariant across distinct access paths.
  - `github-capability-request → Claim` introduces an unnamed 'local requesting Agent' even though the request structure carries no claimant identity. `authorization-regime → Order` likewise lacks an established plurality of Agents because Engram remains unmapped as an Agent and tmux, GitHub, and child processes are not shown to satisfy Agent. These mappings bypass the dependencies later used to describe the authority path.
  - The path titled 'remote input to terminal consequence' overstates demonstrated causal efficacy. The cited code proves guarded delivery of text or keys to tmux, local recording, and a later bounded capture; it does not join the input Difference to a named downstream Change or observed terminal Consequence. A successful send and later refresh cannot supply that bridge.
  - `terminal-source-of-truth → Reference` is not supported as written. The cited source treats tmux as the live workspace and operational authority for current terminal facts, whereas an Organon Reference must be a Map paired with a Specification of Scope, Constraints, and enumerated distortions. The live tmux target is not thereby a Representation or Map.

Evidence: The candidate is notably disciplined about major non-entailments: it rejects repository tests as `organon:Evidence`, rejects tmux idiom as `organon:Truth`, declines Permission/Grant/Receipt promotion, distinguishes Watch, pane, Frame, and anchor, and explicitly limits institution and production claims. Those findings are faithful to `requirements/INDEX.md:3-24`, `docs/design-principles.md:215-234`, and the GitHub broker sources. Its engineering paths also cite genuinely connected stages: admission in `internal/app/app.go:436-455`, current-route and binding checks in `internal/app/input.go:56-180`, tmux-side guarded effects in `internal/tmux/tmux.go:509-561`, and exact GitHub scope validation in `internal/githubauth/client.go:189-216`. However, these strengths do not close the positive mappings above. In particular, `internal/app/app.go:553-560` identifies an authorized account, not an Organon Agent; `docs/design-principles.md:53-60` establishes actionable-anchor uniqueness, not an Entity Boundary; `internal/githubauth/types.go:28-47` carries a pane binding and requested scope but no asserting Agent or Principal; and the input implementation records a successful send without proving a downstream shell result. The manifest's unqualified `exact` and `refinement` classifications therefore conflict with the prose's own promotion gates.

## kenogram-project-ontology

- Artifact: `project-ontology`
- Disposition: **revise**
- Preserve:
  - project-local vocabulary before Organon mapping
  - exact public source citations and nonclaims
  - every conflict, uncertainty, and anti-collapse distinction already established
- Required changes:

### Organon ontology

- Revision: Retain the strong source and nonpromotion boundaries, but make incomplete profiles explicitly conditional or unmapped rather than stable-ID refinements. Separate the represented semantic Rule from the parser/planner Tool that executes it. Define any Specification as a complete Configuration naming its Representation, Denotation target, Scope, and constructive decision procedure. Map the loopback mechanism to Interface only after identifying the Boundary Configuration, coordinating Entities, and represented permitted Transformations. Reclassify per-world history as an ordered Record system unless it is extended to preserve every required Ledger distinction, producer, and Standing. Reclassify `allow`, network allowance, runtime governance, project governance, and applied-plan canonicality as local mechanical vocabulary until an actual Order and complete institutional chain are named. For Entity claims, state one exact Invariant, ordered States, and Persistence witness; otherwise retain Configuration. Replace the claimed causal path with either an explicitly labeled workflow trace or a table enumerating each Transformation, input/output State, shared Direction, and Feeds join. For Observation and Evidence, name the sensing Entity and Boundary, field-level inspection path, claimant, exact Claim, Witness, IndependentFor constraints, governing Order, Admissibility Rule, Admission, evaluation Rule, and recorded disposition. Remove direct Agent, Tool, Organ, Institution, and Canonical-system assertions where their identity or institutional dependencies remain only hypothetical.
- Critical violations:
  - Several `refinement` mappings attach stable Organon IDs even though the local meanings omit constitutive conditions. Most importantly, `allow_operation` and `network allowance` lack the Order, Standing, Authority, Principal, Permission Claim, Grant, and Admission chain required for `organon:Grant` and `organon:Permission`. These should remain unmapped or conflict mappings until a deployment supplies the complete chain.
  - `semantic planner / validator` is mapped to `organon:Rule` primarily because the executable mechanism maps inputs to outputs. An Organon Rule is a Specification of a Constraint or Transformation, not the validating Tool merely because it executes that specification. The rule representation and validator mechanism must be distinguished.
  - The named loopback byte stream is mapped to `organon:Interface` without identifying it as a Boundary Configuration, the coordinating Entities, and the represented permitted Transformations. A named endpoint or stream alone does not satisfy the Interface definition.
  - The per-world hash-chained history is mapped to `organon:Ledger` even while the ontology admits that it does not preserve the required distinctions among Claims, Permissions, Observations, Evidence, Attestations, and Receipts, including producer and Standing. Ordered records alone are not an Organon Ledger.
  - The asserted joined causal path is a workflow trace rather than a complete `organon:CausalPath`: it does not enumerate input and output States, Transformations sharing one Direction, or the Feeds account between adjacent Transformations. The inspection step also invokes Sense and Observation without naming the sensing Entity, its Boundary constraints, and the specified Environment-to-Sense causal path.
  - Materialized-generation Entity status is described as having an explicit identity criterion, but the cited generation names, digests, and runtime fields do not themselves state one preserved Invariant or provide its Persistence witness across the ordered lifecycle States. The document later acknowledges this missing bridge, so the positive wording and stable-ID refinement mapping are premature.

Evidence: The ontology is strongly source-pinned and unusually disciplined about epistemic and institutional limits. It correctly preserves Kenogram's disclaimers, distinguishes declared, implemented, observed, and Organon Evidence, treats local runtime `Evidence` and manifests as producer Records rather than independent Evidence, and refuses to promote hashes into identity or Truth. It also correctly marks local `declaration`, `world`, `authoritative generation`, and backend `Evidence` as conflicts with the corresponding Organon terms, distinguishes capability from institutional authority, and treats scoped network nonavailability as other than `organon:Absence`. The authority and evidence sections explicitly state that deployment-specific Standing, Principal, Authority, IndependentFor, Admission, Order, and evaluation-Rule joins are external promotion gates; thus no production security, certification, adoption, Truth, or Evidence claim is improperly established. However, that discipline is not applied consistently to the refinement mappings. Rule, Interface, Ledger, Entity, Tool/Organ, Order/Institution, Grant/Permission, Observation, Attestation, and Canonical-system profiles are mapped before their earlier dependencies or exact witnesses are supplied. The causal workflow connects relevant Kenogram components and is supported by the cited source, but it does not satisfy Organon's formal Causal-path joins. These are load-bearing mapping defects, so the ontology is not yet review-ready at the score-3 threshold.

### open-source documentation

- Revision: Add a short maintenance section naming explicit re-review triggers: repository commit or source-digest change; Organon version change; declaration or plan schema change; lifecycle authority-state change; network-invariant change; governed-job evidence, verifier, or publication-contract change; and changes to the local meanings of world, declaration, authority, evidence, or generation. State how a maintainer should refresh citations, rerun mappings, and record unresolved changes. Reconcile the YAML manifest with the prose mapping table by making it complete or labeling it as a deliberately bounded subset. Split compound mappings where one citation does not support every component. Correct the opening disclaimer citations so production stability, multi-tenant hardening, compliance, and certification each point to their exact supporting lines. Finally, compress the densest classification sentences and remove or shorten the concluding recap so the document stops after its actionable gates and maintained mapping artifact.

Evidence: The ontology is broadly review-ready. It pins the repository and commit, uses commit-specific file-and-line links throughout, treats repository self-description as declared or implemented rather than independent proof, and reconstructs actors, boundaries, lifecycle states, transformations, authority paths, evidence paths, nonclaims, and promotion gates without becoming a feature inventory. Its progression closely follows the required cadence: scope and purpose precede local vocabulary, followed by participants, load-bearing paths, mappings, boundary cases, and unresolved gates. Local terms such as declaration, world, authority, evidence, generation, and world-pattern are defined before mapping, and exact/refinement/conflict/unmapped outcomes remain distinct. Traceability falls short of exemplary because a few compound claims exceed their cited ranges: the opening nonclaim citation does not directly cover every listed disclaimer, and some compound machine mappings cite only part of the named mechanism. Maintenance readiness is the main weakness. The document pins the current snapshot and records uncertainty, but it does not state operational drift triggers or a re-review procedure. The machine-consumable manifest also omits several mappings present in the prose table, including generation/Configuration, replacement/Transformation, network invariants, Permission, and CanonicalSystem, without identifying itself as a subset. Sentences generally preserve actors and mechanisms, though several classification paragraphs are dense, and the concluding recap repeats distinctions already established.
